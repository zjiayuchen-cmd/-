名场面 · 产品需求文档

一句话定义：把每个人的名字，变成一场猜谜。

1问题定义

1.1 问题陈述

在黑客松、研学营、组队工作坊等短周期高强度协作场景中，开场 10 分钟内的破冰质量直接决定后续协作效率，但现有方式普遍失效：

现有做法失效点
轮流自我介绍被动听 + 信息过载，3 分钟后几乎全忘；内向者应付了事
桌游 / 真心话大冒险需要道具与场地，冒犯风险高，与"记住彼此"目标脱节
直接开工不做破冰后续反复出现"那个谁""黄衣服那个"，协作成本持续外溢

核心矛盾：名字是最需要被记住的信息，却是最抽象、最缺乏记忆抓手的信息——记住"张三"远难于记住"一个会弹吉他、养了两只猫的人"。

1.2 问题本质

这不是"气氛不够热闹"的问题，而是信息编码方式错误的问题。传统的自我介绍把大量抽象标签一次性灌给听众，认知负荷高且无检索线索；而记忆术的基本原理是为抽象信息附加具体视觉锚点（Baker/baker 悖论：附带形象的名词回忆率显著高于抽象名词）。

1.3 机会点

用 AI 把"名字 → 视觉意象"的联想工作自动化。谐音/会意的图像化联想原本需要人的脑洞（这也是它一直只在小范围口耳相传的原因），大模型让这件事可以实时、批量、零门槛地完成，使一个流行于学生课间的土办法变成可规模化复制的产品。

1.4 验证依据（真实案例）

案例场景结果
高中课间活动数学老师组织，全班组名同学生成图片全班参与热烈，外班同学聚集围观
研学营首日任务要求记住全组人名字，采用本方法组员主动开始猜图、互相确认，在玩的过程中自然记住全组名字并熟络
方法在无产品、纯手工的条件下已被验证两次有效；本产品要做的是把手工环节自动化，并补齐游戏闭环。

2目标用户与场景

2.1 目标用户

主用户：活动组织者（房主）

  • 黑客松队长 / 研学营带队老师 / 团建组织者 / 工作坊主持人
  • 特征：有明确的"让大家快速熟起来"的诉求，愿意花 5–12 分钟，但不想准备道具、不想当主持人
  • 核心诉求：低准备成本 + 现场效果好 + 不尴尬

次用户：参与者（组员）

  • 特征：彼此陌生，多数是内向者，不喜欢被点名表演
  • 核心诉求：参与门槛低、不被冒犯、能有个说得出口的理由去认识别人

2.2 核心使用场景

场景组规模时长关键约束
黑客松开场（主场景）4–6 人/组8–12 分钟有投屏，之后立刻要分工协作
研学营首日4–8 人10–15 分钟可能无投屏，需手机传阅兜底
团队 / 班级破冰6–10 人10–15 分钟社交风险敏感，需强防冒犯

2.3 用户旅程（黑客松开场场景）

09:00  队长打开链接创建房间，把二维码投屏
09:01  组员扫码 → 输入名字 → 选 3 句自我介绍（2 真 1 假）
09:03  全员就绪，队长点开始；AI 生成中，大家闲聊
09:04  生成完成，进入竞猜：4 张图拼出一个名字，全场抢答
09:08  名字全部猜中；每题揭晓后追问"两真一假"彩蛋
09:11  本人就真的那条开讲 30 秒，其他人追问
09:12  生成"谐音全家福"海报，扫码保存
09:13  队长：好，我们知道谁会写前端了 —— 开工

3核心功能与流程

3.1 功能架构（四个模块）

名场面
├── A. 房间与入组      创建房间 / 二维码 / 实时成员列表 / 自我介绍采集
├── B. AI 生成管线     姓名单字拆解 → 视觉提示词 → 文生图 → 合规过滤
├── C. 游戏主循环      出题 → 抢答 → 字卡翻转揭晓 → 两真一假彩蛋 → 本人开讲
└── D. 结算与传播      谐音全家福海报 / 保存 / 分享 / 再开一局

3.2 核心流程详解

A. 房间与入组

  1. 房主打开网页链接，一键创建房间，生成二维码 + 4 位房间码
  2. 成员扫码进入极简页：输入名字 → 从系统候选中选 3 句自我介绍（勾选 2 真 1 假）
  3. 成员列表实时同步到房主屏幕，全员就绪后解锁「开始生成」
  4. 无需注册、无需登录、无需下载
设计要点：自我介绍由系统提供候选池而非用户手写——现场没人能在 30 秒内写出好素材，给选项才能保证完成率与趣味性下限。

B. AI 生成管线（两段式，关键架构）

姓名
 └─ ① LLM 创意拆名
      · 逐字拆解：字形拆解（张→弓+长） / 谐音（宇→鱼） / 会意（辰→沉）
      · 输出结构化：{元素, 对应字, 解释文案, 视觉提示词}
 └─ ② 合规过滤
      · 负面谐音黑名单（朱→猪 类）
      · 名字主人可一票否决 / 重 roll
 └─ ③ 文生图 API
      · 统一"贴纸/扁平插画风"，规避写实风恐怖谷
      · 每字一张独立图标 → 网格拼合（而非一张图硬塞 4 个元素）
 └─ ④ 自我介绍图标化
      · 3 句介绍同步生成对应图标，进入彩蛋卡池
架构要点：真正需要"脑洞"的是拆名环节，必须交给 LLM 而非文生图模型。直接把名字丢给画图模型效果不可用。这条管线本身是提案的技术叙事重点。

C. 游戏主循环

  1. 出题：图片打乱顺序，投屏或房主手机展示"这 4 张图拼成了一个名字"
  2. 抢答：口头抢答，不做任何点击投票（防低头设计的核心约束）
  3. 揭晓：字卡逐个翻转成汉字 + 谐音拆解动画 —— 记忆形成于揭晓那一刻
  4. 彩蛋 · 两真一假：三张标签卡滑出（三句自我介绍的图标化版），大家猜哪句是编的；点卡翻牌，真变绿 / 假标红
  5. 本人开讲：揭晓后提示"轮到 XX 本人挑一句真的展开说说（30 秒），大家随便追问"
  6. 循环至全部成员，进入结算

D. 结算与传播

  • 生成「谐音全家福」海报：每人一行 = 名字 + 拆解图标 + 2 条真实情报 chip
  • 扫码保存 / 分享 —— 天然的合影替代品与传播素材
  • 一局 4 人 = 挖出 8 条真实情报，海报即一份带脸的技能花名册

3.3 防低头设计（贯穿性约束）

这是本产品的生死线：手机是门票，不是座位。
约束说明
手机角色仅用于入组与保存海报，合计 ≤1.5 分钟
进行时屏幕一块屏原则：投屏优先，无投屏则房主手机平放桌中或笔记本开链接
操作主体竞猜全部口头完成，只有房主代点
输出物游戏的输出是对话，不是屏幕时间
计分方式只记"场面分"（如"隔壁组围观 +2"），不做个人排行榜

反模式警告：把投票/答题/计分做成人人一屏在工程上最省事（无需同步房主状态），但体验上会直接退化成"大家坐一起玩手机"。宁可保持讨论靠嘴、操作由房主代点。

4产品形态

4.1 形态选择：H5 网页链接

维度网页链接 H5　✅小程序　❌
触达链接 / 二维码即点即玩需搜索或扫特定码
迭代比赛期间随时热更每次更新需过审
跨平台微信内置页 / 浏览器 / 电脑均可开基本绑定微信
用户成本零下载 · 零注册 · 零存储加载包体、授权弹窗

结论：对一个"临时拉起来的局"，一个 URL 就是全部传播路径——发群里、投屏上贴二维码即可。

4.2 三种现场投放模式

模式条件做法
投屏模式（最佳）有投影 / 大屏房主屏幕投屏，全员抬头看
桌面模式（兜底）无投屏房主手机平放桌子中央
传阅模式（极端）无网络 / 无设备收集名字后手工出题，仍可跑通核心玩法

5量化指标

5.1 北极星指标

记名率：活动结束 10 分钟后，参与者平均能正确叫出的组员名字数 / 总人数。

之所以测"10 分钟后"而非"当场"，是因为当场记得不算数——延迟回想起的正确率才能证明形成了真实记忆锚点。

5.2 指标矩阵

层级指标目标值测量方式
北极星延迟记名率显著高于传统自我介绍组结算前嵌入"点头像选名字"小测验
认知情报留存数≥ 2 条真实信息 / 人海报 chip 数 / 彩蛋揭晓数
体验参与度主动开口人数 ≥ 组规模 60%抢答发言计数
体验低头率个人屏幕时间占比 < 15%单机时长埋点
体验舒适度"敢直接叫组员名字"自评 ≥ 4/5结算后一句话评分
业务完成率一局完整走完 ≥ 90%开始 / 结束埋点
业务传播海报保存 / 分享率 ≥ 40%保存按钮埋点

5.3 验证计划

关键设计：把测验环节内置于结算页——在全家福海报之前加一步"来，测测你能叫出几个人的名字"（点头像选名字）。好处有三：

  1. 每一次真实开局都自动积累数据，零额外验证成本
  2. 测验本身强化一遍记忆（等于免费多复习一轮）
  3. 提案中可写"产品内置效果追踪，每次对局自动生成验证数据"

比赛前置验证：答辩前找 8 人分两组（实验组玩产品 / 对照组轮流自我介绍），纸笔测试 10 分钟后记名率，拿到第一个数字。

诚实声明：4–6 人小组样本量做不出统计显著性，报告中须注明"小样本"，不得夸大。评委不苛求 P 值，苛求的是度量的意识。

6.2 P1（比赛后迭代）

  • 自我介绍候选池（结构化采集，替代手写）
  • 两真一假彩蛋环节（原型已设计，可先简化为口头）
  • 结算页内置记名率测验
  • 生僻字 fallback：字源拆解 → 含义联想 → 跳过
  • 生成期填充环节（自我介绍 / 闲聊引导）

6.3 P2（长期）

  • 多语言 / 英文名支持（当前明确不做，机制基于汉字，硬扛会稀释体验）
  • 队伍技能标签聚合与分工建议
  • 跨场次数据沉淀、团队记忆库

6.4 明确不做

  • ❌ 账号体系 / 用户注册
  • ❌ 个人排行榜 / 竞技排名（反防低头设计）
  • ❌ 小程序版本（成本收益不成立）
  • ❌ 国际化名字支持

7风险应对

7.1 风险清单

#风险等级应对措施
R1社交风险：谐音冒犯🔴 高负面谐音黑名单；名字主人一票否决 / 重 roll；生成后仅本人可见一次确认机会
R2体验退化：变成一起玩手机🔴 高一块屏原则；口头抢答；只有房主可操作；不做个人排行榜（见 3.3）
R3生成质量：恐怖谷🟠 中统一贴纸 / 扁平插画风；每字独立图标而非一张图塞多元素；单张可重 roll
R4技术：生僻字 / 多音字拆不动🟠 中三级 fallback：字源拆解 → 含义联想 → 标注"此字留给大家自由发挥"；赛前用生僻字压力测试
R5延迟：6 人 × 20 秒很尴尬🟠 中批量并发生成；生成期设计填充话术（"趁现在聊聊待会儿的两真一假，但别剧透"）
R6现场设备不可靠🟠 中三种投放模式（投屏 / 桌面 / 传阅）；核心玩法手工可兜底
R7API 成本与 Key 安全🟡 低Key 仅存本地，绝不上传服务端；限制单房间生成次数
R8隐私：真名采集🟡 低界面明示用途；对局结束即释放；不做持久化存储
R9多音字歧义（如"重""行"）🟡 低LLM 拆名时生成多版本候选，房主 / 本人在入组时选定

7.2 Top 2 风险的深度应对

R1 谐音冒犯（最需警惕）

谐音梗是双刃剑。"朱→猪"这类映射对名字主人可能造成真实伤害，且在黑客松现场被公开玩梗的尴尬会直接反噬产品的"氛围"定位。因此：

  • 生成前：LLM 侧过滤负面联想词表
  • 生成后：名字主人拥有唯一裁决权——预览到自己名字的图，可一键重 roll，无需向他人解释
  • 兜底：若三次重 roll 仍不满意，允许跳过该成员进入下一环节

R2 体验退化（最易发生）

见 3.3 防低头设计。核心是在架构上不给"各自盯屏"留接口——只要不实现组员端的投票 / 答题 / 计分，退化就不会发生。这条要在开发排期时就作为硬约束写入，而不是上线后靠运营补救。
